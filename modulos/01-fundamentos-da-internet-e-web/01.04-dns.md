## Ideia Central

DNS é o sistema que ajuda a transformar nomes legíveis, como `exemplo.com`, em endereços que computadores conseguem usar para encontrar o destino.

Pessoas preferem nomes. Máquinas precisam de endereços. O DNS existe para aproximar essas duas necessidades.

Quando você digita uma URL no browser, antes de pedir o conteúdo ao servidor, o sistema precisa descobrir para onde esse pedido deve ir. O DNS participa dessa descoberta.

## Anatomia de Uma URL

Antes de falar de DNS, vale separar algumas palavras que costumam aparecer juntas.

Uma URL completa pode ter várias partes:

```text
https://app.petcareos.com.br/pets/123/status?aba=resumo#historico
```

| Parte | Exemplo | O que significa |
| --- | --- | --- |
| **Protocolo ou esquema** | `https://` | Indica como o browser pretende conversar com o destino. |
| **Subdomínio** | `app` | Uma divisão dentro do domínio principal. |
| **Domínio** | `petcareos.com.br` | Nome legível usado para localizar um serviço. |
| **Path** | `/pets/123/status` | Caminho do recurso dentro da aplicação. |
| **Query string** | `?aba=resumo` | Parâmetros extras enviados na URL. |
| **Fragmento** | `#historico` | Aponta para uma parte específica da página; normalmente é tratado pelo browser. |

O DNS entra principalmente na parte do **nome**: ele ajuda a descobrir para qual
endereço o domínio ou subdomínio aponta. O path, a query string e o fragmento
não são resolvidos pelo DNS; eles fazem sentido depois que o browser já sabe para
onde enviar a comunicação.

Também é importante separar três ideias:

- **URL** é o endereço completo usado pelo browser.
- **Domínio** é o nome legível, como `petcareos.com.br`.
- **Servidor** é quem recebe pedidos e devolve respostas; um domínio pode apontar
  para diferentes infraestruturas ao longo do tempo.

## Exemplo Prático

Imagine que um tutor quer acessar `app.petcareos.com.br` no celular.

O browser não "adivinha" onde o portal do PetCare OS está. Ele precisa descobrir qual endereço IP está associado ao nome `app.petcareos.com.br`. Essa consulta pode passar por caches e servidores DNS até encontrar uma resposta.

Somente depois disso o browser consegue enviar a requisição para o servidor correto.

## Analogias e Intuições

- DNS é como uma agenda que traduz nomes para endereços.
- Domínio é um nome fácil para humanos; endereço é uma referência útil para máquinas.
- URL é o endereço completo no envelope; domínio é a parte que ajuda a encontrar o destino.
- Cache de DNS é como lembrar uma resposta recente para não perguntar tudo de novo.

## Erros Comuns

- Achar que comprar um domínio cria automaticamente um site completo.
- Confundir URL completa com domínio.
- Achar que o DNS resolve o path ou a query string, quando ele participa da descoberta do nome.
- Confundir domínio com servidor.
- Confundir DNS com HTTP.
- Esperar que mudanças de DNS apareçam instantaneamente em todos os lugares.
- Esquecer que caches podem manter respostas antigas por algum tempo.
