## Ideia Central

Um protocolo é um conjunto de regras para comunicação.

Quando dois sistemas precisam conversar, eles não podem improvisar totalmente. Eles precisam combinar formato, ordem, significado e comportamento esperado das mensagens.

Na Web, protocolos ajudam máquinas diferentes, sistemas diferentes e programas diferentes a se entenderem. Sem protocolos, cada aplicação falaria de um jeito e a comunicação ficaria imprevisível.

Uma comunicação Web não depende de um único protocolo. Diferentes protocolos
trabalham juntos, cada um cuidando de uma parte do caminho: encontrar o destino,
endereçar os dados, transportá-los, proteger a comunicação e organizar pedidos
e respostas.

### O Que São Pacotes

Quando um sistema envia dados pela rede, ele normalmente não manda tudo como uma
peça única. Os dados são divididos em partes menores chamadas **pacotes**.

Um pacote pode ser imaginado como um pequeno envelope que carrega:

- uma parte do conteúdo;
- informações de origem e destino;
- informações de controle usadas pelos protocolos.

Essa divisão permite que dados grandes atravessem redes diferentes em partes
menores. Uma página, uma imagem, um vídeo ou uma resposta de API podem ser
transportados como muitos pacotes que seguem pelo caminho e depois são
interpretados pelo destino.

Nem todo protocolo oferece as mesmas garantias sobre esses pacotes. Alguns se
preocupam em garantir ordem e entrega. Outros priorizam velocidade e menor
sobrecarga. Essa diferença é um dos motivos pelos quais existem protocolos
diferentes para problemas diferentes.

### Mapa dos Protocolos Principais

Neste momento, o objetivo não é memorizar detalhes. Use a tabela como um mapa
inicial do problema que cada protocolo ajuda a resolver.

| Protocolo | Papel principal | Pergunta que ajuda a responder |
| --- | --- | --- |
| **IP** | Endereça e encaminha pacotes entre redes. | Para qual endereço os dados precisam seguir? |
| **TCP** | Cria uma comunicação confiável e ordenada entre dois pontos. | Como garantir que os dados cheguem completos e na ordem? |
| **TLS** | Protege a comunicação com criptografia, autenticação e integridade. | Como evitar que terceiros leiam ou alterem os dados durante o caminho? |
| **DNS** | Ajuda a encontrar o endereço associado a um nome de domínio. | Para qual endereço corresponde `exemplo.com`? |
| **HTTP** | Define pedidos e respostas para transferir recursos e dados na Web. | Como o cliente pede algo e como o servidor responde? |

**HTTPS** significa que a comunicação HTTP está protegida por TLS. Portanto, não
é necessário pensar em HTTPS como um substituto independente de HTTP: são as
regras do HTTP sendo usadas dentro de uma conexão protegida.

Existem muitos outros protocolos importantes na Internet. Alguns são usados para
e-mail, acesso remoto, transferência de arquivos, comunicação em tempo real,
streaming, jogos, chamadas de voz e outras necessidades. Eles são tão relevantes
quanto os listados aqui, mas não precisam entrar no centro desta aula. O objetivo
agora é entender a ideia de regras combinadas e reconhecer os nomes que aparecerão
no restante deste módulo.

## Exemplo Prático

Pense em uma conversa simples:

1. Uma pessoa cumprimenta.
2. A outra responde.
3. Uma pergunta é feita.
4. Uma resposta é dada.
5. As duas sabem quando a conversa acabou.

Se cada pessoa seguir uma regra completamente diferente, a conversa falha.

Protocolos fazem algo parecido entre sistemas: definem como uma mensagem deve ser enviada, interpretada e respondida.

Agora imagine que essa conversa precisa acontecer por cartas, mas cada carta só
pode carregar uma parte pequena da mensagem. A mensagem completa precisa ser
dividida, enviada em partes e interpretada corretamente por quem recebe.

Pacotes cumprem um papel parecido na rede: eles são pedaços menores de uma
comunicação maior.

Ao abrir uma página com HTTPS, vários protocolos podem participar:

```text
DNS encontra o endereço do serviço
        ↓
IP ajuda os pacotes a atravessarem redes
        ↓
Transporte e segurança:
- TCP ajuda a transportar os dados com confiabilidade
- TLS protege a comunicação quando usamos HTTPS
        ↓
HTTP organiza o pedido e a resposta
```

Essas responsabilidades são diferentes, mas trabalham juntas. A aula de DNS e
a aula de HTTP aprofundarão duas dessas partes mais adiante.

## Analogias e Intuições

- Protocolo é como um idioma combinado entre sistemas.
- Protocolo é como uma etiqueta de atendimento: pedido, confirmação, resposta e encerramento.
- Protocolo é uma regra compartilhada para evitar ambiguidade.
- Pacotes são como envelopes pequenos dentro de uma entrega maior: cada um carrega uma parte do conteúdo e informações para ajudar no caminho.
- Protocolos em camadas são como etapas de uma entrega: uma regra identifica o endereço, outra cuida do transporte, outra protege o conteúdo e outra define como interpretar o pedido.
- Em uma clínica veterinária, o fluxo de triagem segue uma ordem: a recepção registra o tutor, o clínico avalia o pet e o sistema registra o atendimento. Se cada profissional seguir uma ordem diferente, o atendimento vira caos. Protocolos fazem algo parecido entre sistemas.

## Erros Comuns

- Achar que protocolo é sempre uma ferramenta ou biblioteca.
- Imaginar que uma página ou resposta viaja inteira pela rede como um único bloco.
- Confundir pacote com arquivo. Um arquivo pode ser dividido em muitos pacotes durante o transporte.
- Decorar siglas sem entender o problema que elas resolvem.
- Misturar Internet, Web e HTTP como se fossem a mesma camada.
- Pensar que um único protocolo resolve toda a comunicação.
- Achar que HTTPS substitui HTTP, quando ele representa HTTP protegido por TLS.
