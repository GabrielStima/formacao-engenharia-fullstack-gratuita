## Ideia Central

Frontend e backend são papéis dentro de uma aplicação web.

Em uma frase curta: **frontend é a parte da aplicação que a pessoa usa
diretamente; backend é a parte que valida, processa, protege, persiste e responde
por trás da interface**.

Frontend é a parte mais próxima da interação com a pessoa usuária. No contexto da Web, normalmente roda no browser e lida com interface, eventos, apresentação, navegação e chamadas para obter ou enviar dados.

Backend é a parte que roda do lado do servidor ou de serviços remotos. Ele lida com regras, autenticação, persistência, integrações, processamento e respostas para clientes.

Esses papéis podem aparecer de formas diferentes conforme a arquitetura, mas a separação ajuda a entender responsabilidades.

## Analogia: Salão e Cozinha

Uma aplicação web pode ser comparada a um restaurante.

O frontend é o salão: é onde a pessoa vê o cardápio, faz escolhas, recebe
orientação, interage com o atendimento e percebe a experiência.

O backend é a cozinha e a operação interna: é onde pedidos são conferidos,
ingredientes são buscados, regras são aplicadas, pratos são preparados e decisões
críticas são tomadas antes de algo chegar ao salão.

```text
Cliente no salão
      ↓
Garçom anota o pedido
      ↓
Pedido vai para a cozinha
      ↓
Cozinha confere ingredientes, regras e preparo
      ↓
Prato volta para o salão
      ↓
Garçom apresenta o resultado ao cliente
```

Na Web, o fluxo é parecido:

```text
Pessoa usuária
      ↓
Frontend no browser
      ↓
Request HTTP
      ↓
Backend no servidor
      ↓
Response HTTP
      ↓
Frontend atualiza a tela
```

| Característica | Frontend: o salão | Backend: a cozinha |
| --- | --- | --- |
| **Aparência e interação** | Decoração, mesas, cardápio, atendimento, clareza da experiência. | Fogão, despensa, panelas, fila de preparo e organização interna. |
| **Profissional equivalente** | Garçom e maître: ajudam a pessoa a entender opções e ser bem atendida. | Chef, estoquista e equipe interna: garantem preparo, regras e ingredientes corretos. |
| **Onde acontece na Web?** | Normalmente no browser do usuário, como Chrome, Safari, Firefox ou Edge. | Em servidores, data centers, cloud, serviços gerenciados ou infraestrutura interna. |
| **Foco principal** | Experiência do usuário, apresentação, acessibilidade, eventos, responsividade e estado de tela. | Segurança, regras de negócio, processamento, persistência, integrações e performance de dados. |
| **Erro comum** | Achar que é só beleza visual. | Achar que é só banco de dados. |

O limite da analogia: em software, algumas responsabilidades podem se misturar.
O frontend também pode ter lógica de interação e validações simples. O backend
também precisa pensar na experiência, porque respostas lentas, erros confusos e
regras mal desenhadas afetam diretamente quem usa o sistema.

## Exemplo Prático

Na tela de aprovação de orçamento do portal do tutor:

- o frontend mostra o valor total, os itens listados e o botão de aprovar;
- o frontend valida se o tutor realmente clicou em aprovar e pode pedir uma confirmação;
- o frontend envia uma request para o backend;
- o backend valida se o orçamento ainda está válido, se o tutor tem permissão e se o saldo/crédito está adequado;
- o backend registra a aprovação ou rejeita com um erro;
- o backend devolve uma response;
- o frontend mostra o resultado para o tutor.

Frontend e backend trabalham juntos no mesmo fluxo.

## Analogias e Intuições

- Frontend é a camada de interação; backend é a camada de processamento e regras.
- Frontend pergunta e apresenta; backend decide, busca, grava e responde.
- Frontend é como o salão de um restaurante: visível, interativo e responsável pela experiência direta.
- Backend é como a cozinha: processa pedidos, aplica regras, consulta estoque e entrega um resultado confiável.
- A fronteira entre frontend e backend é uma decisão de responsabilidade, não só de ferramenta.

## Erros Comuns

- Achar que frontend é "só visual".
- Achar que backend é "só banco de dados".
- Achar que o salão e a cozinha são independentes. Se a cozinha atrasa, o salão sofre; se o salão anota errado, a cozinha prepara errado.
- Confundir frontend/backend com linguagem específica.
- Colocar regra crítica apenas no frontend.
- Pensar que toda aplicação precisa ter a mesma divisão interna.
